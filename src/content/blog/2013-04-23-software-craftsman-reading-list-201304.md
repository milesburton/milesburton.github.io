<p>It&#8217;s a little bit overdue since I updated my recommended reading list so here we go. This is a mixture of books that I would highly recommend you read. There&#8217;s something suitable for everyone. If you have any recommendations for me please leave a comment!</p>
<p><strong>REST/Web-services</strong></p>
<ul>
<li><span style="line-height:14px;">Rest API Design Rulebook &#8211; Really succinct book on REST API design and practises </span></li>
<li>Rest in practice &#8211; Good book. Covers all avenues of REST &#8211; desperately needs a TLDR; version</li>
</ul>
<p><strong>Front-end web development:</strong></p>
<ul>
<li>Effective Javascript &#8211; Work past the &#8216;Oh I know that&#8217; bits and enjoy some fresh insights into ECMA Script</li>
<li>JavaScript the Good Parts &#8211; Another &#8216;just read it&#8217; book. Pragmatic approach to JavaScript development. A must read.</li>
<li>Response Web Design &#8211; Ethan Marcotte &#8211; If you are new to Responsive Web Design Ethan takes you step by step explaining why RWD is important and how to implement it successfully.</li>
</ul>
<p><strong>Interviews:</strong></p>
<ul>
<li><span style="line-height:14px;">Cracking the Coding Interview &#8211; Really good, I would highly suggest working through the examples. Helps dust off the old cobwebs &#8211; would I recommend interviewing like this? No but it&#8217;s still good to know.</span></li>
<li>Programming Interviews Exposed &#8211; Not quite as good as Cracking the Coding Interview but covers a lot of basic computer science basics. A good refresher with good examples.</li>
<li>How would you move mount Fuji &#8211; A mind bender of a book. Thank lord interviews don&#8217;t tend to do this any more (except Amazon). This book comes from Microsoft&#8217;s heyday back in the 90&#8217;s when lateral thinking was all the rage. At a minimum it&#8217;s good fun to read and you can wind up your workmates something chronic with the examples 😉</li>
</ul>
<p><strong>Java:</strong></p>
<ul>
<li><span style="line-height:14px;">Effective Java (2nd Edition) &#8211; Just read it<br />
</span></li>
<li>Java Concurrency In Practise &#8211; Well worth a read. Explains some of the patterns and gotchas of concurrent development</li>
<li>Thinking In Java &#8211; A bit of a Tome but covers a vast wealth of topics. It is a must read and I&#8217;d highly suggest booking a couple of days to read through it slowly.</li>
</ul>
<p><strong>Craftsmanship:</strong></p>
<ul>
<li><span style="line-height:14px;">Growing Object oriented Software &#8211; Guided By Tests &#8211; a good, if slow introduction to TDD and OO<br />
</span></li>
<li>Cleancoder[s] &#8211; Read both, now. Fantastic &amp; fun introduction to software craftmenship</li>
<li>The Pragmatic Programmer &#8211; I cannot recommend this book any more. Great for junior developers who are trying to get their head around the software craftmenship movement</li>
<li>Refactoring &#8211; Improving the Design of Existing Code &#8211; This is good, I&#8217;d consider it &#8216;revision&#8217; for an experienced developer. It is a bit of an effort to read but has many good examples and tips.</li>
<li>Head First Design Patterns &#8211; Only applicable for junior developers. Well worth a read</li>
<li>Head First Software Development &#8211; Great introduction to Agile Development and without a doubt a precursor to &#8216;The Pragmatic Programmer&#8217;</li>
</ul>
<p><strong>Software Architecture:</strong></p>
<ul>
<li><span style="line-height:14px;">User Stories Applied &#8211; I was a little hot and cold on this book. It feels rather outdated in 2013. That said, it heats up around half way through the book (feel free to skip). Some very good practical advise for running a scrum team and writing user stories.<br />
</span></li>
</ul>
<p><strong>Low level:</strong></p>
<ul>
<li><span style="line-height:14px;">Assembly Language Step-By-Step &#8211; Programming With DOS And Linux &#8211; I really enjoyed reading this book. It has just enough humour to make an otherwise tricky subject a joy to read. Take it slow, this isn&#8217;t a book to read on the tube. Give it the time it deserves and you&#8217;ll appreciate the nuances of software engineering just that little more. &#8211; oh, this is totally applicable for all levels of developer. I&#8217;d go as far as to say, a must read.</span></li>
<li>Hacker&#8217;s Delight &#8211; This isn&#8217;t for the feint hearted. This book covers some very indepth topics such as bit twiddling. I would recommend adding this book to your arsenal but selecting the chapters which are appropriate for you. It has some really good material but be careful not to accidentally miss the gems.</li>
<li>C++ Algorithms, Data Structure &#8211; Core revision for everything to do with Link lists, balanced trees and all that other gold you ignored at university 😉</li>
</ul>
<p><strong>Agile:</strong></p>
<ul>
<li><span style="line-height:14px;">Scrum and XP from the Trenches &#8211; (Excellent name if I dont say so myself ;)). A pragmatic introduction to Scrum &amp; and XP. Quite a short easy and fun read. Grab a free copy for your tube journey.</span></li>
<li>Extreme Programming Explained &#8211; For those who are new to XP/Agile this /the/ Agile book. EPE was released when Agile was still relatively new which means it has lots of fresh and interesting thoughts which are unimpeded by today&#8217;s &#8216;we work in an agile environment&#8217; spiel. It is a great read especially suited to those who are brand new to XP and Agile.</li>
</ul>
<p><strong>Neuro Linguistic Programming:</strong></p>
<ul>
<li><span style="line-height:14px;">NLP at Work &#8211; This really is a fantastic book. It provides a simple and pragmatic introduction to NLP in the workplace. What simply things can you do to gain rapor and become more persuasive at work.<br />
</span></li>
<li>Introduction to NLP &#8211; A world renowned book for people eager to investigate NLP. It can be tricky to stay with this book and I wouldn&#8217;t be surprised if you find yourself re-reading chapters several times. My recommendation is give yourself time to read it and don&#8217;t be afraid to mark pages and read them again when you are in private company.</li>
</ul>
<p>Scarily enough this isn&#8217;t exhaustive any any means. I hope to throw up another list of more technology specific books I&#8217;d recommend you read. This post was mostly looking at books which help you become a better &#8216;software craftsman&#8217;.</p>
