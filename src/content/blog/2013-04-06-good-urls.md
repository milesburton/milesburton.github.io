<p>Just spotted this interesting comment from <a href="https://news.ycombinator.com/item?id=5498198">Hackernews</a>:</p>
<ul>
<li>&#8211; <i>Short over long.</i> Consider removing useless words from the url like news.ycombinator.com/tips-for-designing-good-urls</li>
<li>&#8211; <i>Concise.</i> To the point, describe the page content from the url</li>
<li>&#8211; <i>Use lowercase.</i> Generally the best idea, for sharing links and technical issues (Apache is case-sensitive sometimes)</li>
<li>&#8211; <i>Consistent.</i> Stay consistent, make a style guide for URL&#8217;s if necessary</li>
<li>&#8211; <i>Conscious of trailing slashes.</i> Stick with trailing slashes or no trailing slashes. Redirect to preferred form.</li>
<li>&#8211; <i>Logical.</i> Follow a logical structure, that follows the structure of the site. A good URL might read like a breadcrumb: site.com/category/product-name, this works for silo&#8217;ing your content. Other sites (such as news sites or without a category) might benefit more from the shortest url possible.</li>
<li>&#8211; <i>Using dashes for spaces.</i> No underscores, + or %20 spaces.</li>
<li>&#8211; <i>Not using special chars.</i> Consider replacing é with e and removing any non-alphabet non-number character like: &#8216; &#8221; (</li>
<li>&#8211; <i>Canonical.</i> There should be only 1 unique URL in a search engines index with a page content. Use canonical or 301&#8217;s or smart use of URL&#8217;s to make sure this is the case.</li>
<li>&#8211; <i>Degradable.</i> What happens if a user visits example.com/category/product-name/ and then removes the /product-name/ part? The URL-structure should allow for this and example.com/category/ should return content (preferably the category description)</li>
<li>&#8211; <i>Timeless.</i> If you have an event and you set the date inside the URL, then after this date has passed, this URL gets less valuable. Either 301 these aged URL&#8217;s to the current event URL, or make it so your URL&#8217;s can be &#8220;re-used&#8221; for future events. Cool URLs don&#8217;t change.</li>
<li>&#8211; <i>Optimized for search.</i> Use a keyword tool, to find out what users might be searching for and use the relevant keywords inside your URL. Keyword in URL is a (minute) ranking factor. Bolded keywords in URLs help discoverability.</li>
<li>&#8211; <i>Not using excessive dynamic variables</i>. These will confuse your users and search engines.</li>
<li>&#8211; <i>Flat over deep.</i> Hiding content away in many subdirectories can hamper readability and search engine crawling. Avoid example.com/cat/subcat/subsubcat/widgets/green/second-hand/widget-deluxe/reviews</li>
<li>&#8211; <i>Extension agnostic.</i> An URL ending in .php, .py, .xml, .htm etc. can be changed to another extension in the future, requiring an update or inconsistency in the URLs.</li>
<li>&#8211; <i>Not spammy.</i> Good URL&#8217;s don&#8217;t repeat (slight variations of) keywords or (ab)use extensions like .font or .shoe</li>
<li>&#8211; <i>Not disclosing technology.</i> There is little reason to add cgi-bin to your URLs (unless you want to confuse your competition). An extension to really avoid is the .exe extension (mapserv.exe?doc=15)</li>
<li>&#8211; <i>Non-traversable.</i> When using document IDs all URL&#8217;s can easily be scanned/traversed in a loop or manually. Including URL&#8217;s not yet ready/or never meant for publication.</li>
<li>&#8211; <i>Secure.</i> Not susceptible to injection, XSS etc.</li>
</ul>
<p>Some good advice, well worth considering when you develop your site information architecture</p>
